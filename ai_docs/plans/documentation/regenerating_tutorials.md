# Runbook: regenerating the Phase 2 tutorials

How to reproduce or refresh the four tutorials and their example dataset, and what
is (and is not) deterministic. Companion to `documentation_tutorials.md` (the plan).
Written after the first full execution (issues #15–#21).

## Artifacts and their source of truth

| Artifact | Source | Committed |
| --- | --- | --- |
| `docs/tutorials/data/*` | built deterministically with `random.Random(0)` from `case_study_input/` | yes |
| `docs/tutorials/t1_api_full.ipynb`, `t2_api_basic.ipynb` | authored, executed with real outputs + figures | yes (source of truth) |
| `docs/tutorials/t1_api_full.md` / `_files`, `t2_api_basic.md` / `_files` | `jupyter nbconvert --to markdown` of the `.ipynb` | yes; **also regenerated by RTD at build** (`.readthedocs.yaml`) |
| `docs/tutorials/t3_cli_full.md`, `t4_cli_basic.md` | hand-written; commands + file peeks | yes |
| `docs/tutorials/assets/t3_*.png`, `t4_*.png` | the enrichment figures extracted from the executed T1/T2 notebooks (T1→t3, T2→t4) | yes |

The notebook `_work/` dirs (`t1_work/`, `t2_work/`) are run byproducts (downloaded
FASTA) and are git-ignored — never commit them.

## What is deterministic

Reproduces exactly on rerun:

- **Membrane filter, FASTA/domain download** — content-stable (live, but the data is
  stable): human 276 → **270**; bacterial **243** OMV used directly (no filter).
- **DDI** = **1,848**; **DMI both** = **63,387** (fwd 19,104 / rev 44,283);
  **DMI forward** = **19,104**.
- **IDR filter** (`method=iupred`, cutoffs 0.5) — deterministic, CPU, no model
  download: both = **1,667** (fwd 1,463 / rev 204); forward-only = **1,463**.
- **Monte Carlo** (`seed=0`, `iterations=1000`, `alpha=0.05`): both = **207**
  (fwd 113 / rev 94); **forward-only = 80**. Note forward-only ≠ the forward slice
  of the both run (113): Benjamini–Hochberg is computed over the tests actually
  included, so the threshold differs.

## What is NOT deterministic

- **TieDie is not seeded.** The network varies slightly run to run. Committed values
  (at `permute=10`): comprehensive ≈ **8,639 edges / 2,225 nodes**; forward-only
  default ≈ **4,399 edges / 1,657 nodes**. The tutorials run `permute=10` so they
  finish on any machine, and recommend `permute=1000` for real analyses (on this
  dataset `permute=10` and `permute=1000` give an essentially identical network —
  see #22).
- **Enrichment term counts drift** because they ride on the TieDie node set and the
  live Enrichr/Reactome database. Committed: comprehensive HMI **14**, TieDIE ~**870**
  (seen 869–872 across runs); forward-only HMI **2**, TieDIE ~**795**.
- **Download stages are live** (UniProt, Pfam, OmniPath, Enrichr) and can shift with
  upstream releases.

## How to regenerate the notebooks

1. Env: `uv sync` + extras `[idr,tiedie,enrichment]`, plus `ipykernel` (author-time
   only, not a project dep).
2. **OmniPath TLS workaround (temporary).** `omnipathdb.org`'s certificate is
   currently expired server-side, so author runs force `verify=False` via a local
   shim loaded through an IPython startup file (an `IPYTHONDIR` with a startup
   script that imports the shim) — the committed notebooks contain no such code.
   Remove this once the OmniPath maintainers renew the cert.
3. Execute:
   `jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=2400 t1_api_full.ipynb`
   (then `t2_api_basic.ipynb`), run from `docs/tutorials/` so `data/` resolves.
   The setup cell already handles cleanliness: `%matplotlib inline` (so returned
   figures embed as PNG) and a logging drop-filter for `biothings.client` / `gget`
   (which re-assert their own INFO level on import, so `setLevel` alone does not
   stick).
4. Re-extract the CLI enrichment PNGs from the executed notebooks (T1→`assets/t3_*`,
   T2→`assets/t4_*`).
5. `jupyter nbconvert --to markdown docs/tutorials/t1_api_full.ipynb docs/tutorials/t2_api_basic.ipynb`
   to refresh the committed `.md` + `_files` (RTD does the same at build).

## How to verify

- CLI numbers: run the `microbiolink-*` console scripts (as in T3/T4) against the
  dataset; the compute stages (DDI/DMI/IDR/Monte-Carlo) match the notebook counts
  exactly.
- Site: `zensical build --strict` → "No issues found"; confirm the six
  `site/tutorials/*` pages, the four `assets/` + four `_files/` PNGs, and the
  `data/*.csv` are present and links/anchors resolve.

## Known performance issues (do not block the docs)

- **#22** — TieDie speed/memory (`permute=1000` OOMs on a small-RAM machine).
- **#23** — human membrane filter downloads the whole OmniPath Intercell table; slow
  on a cold cache (~12 min first call of a session), fast once warm (~1.5 s).
